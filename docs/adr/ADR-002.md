# ADR-002: NestJS como framework de backend

## Status
Aceito

## Contexto
O backend será um monólito modular ([ADR-003](ADR-003.md)) em Node.js/TypeScript, precisando de fronteiras de módulo claras, injeção de dependência, e suporte de primeira classe a Guards/Interceptors para aplicar autenticação, multi-tenancy e RBAC de forma consistente em todos os endpoints (ver [../03-architecture/security.md](../03-architecture/security.md)).

## Problema
Qual framework de backend adotar para suportar uma arquitetura modular organizada, com baixo risco de virar um monólito desorganizado ao longo do tempo.

## Opções consideradas
1. **NestJS** — opinativo, estrutura modular nativa (`@Module`), DI nativa, Guards/Interceptors/Pipes de primeira classe, forte tipagem, amplamente adotado para APIs REST TypeScript.
2. **Express puro** — minimalista, flexível, mas exige convenção própria para modularidade, DI e Guards (mais decisões de arquitetura recaem sobre o time, maior risco de inconsistência entre módulos ao longo do tempo).
3. **Fastify puro** — performance superior ao Express, mesmo problema de falta de estrutura opinativa para modularidade/DI.

## Decisão
Adotar **NestJS**.

## Consequências
- Positivas: a estrutura de módulos exigida pela arquitetura (monólito modular, [ADR-003](ADR-003.md)) é o padrão nativo do framework, reduzindo a chance de módulos vazarem responsabilidade um para o outro; Guards/Policies para tenant e RBAC (BR-25) têm suporte de primeira classe; curva de aprendizado é compensada por convenções que múltiplos agentes de IA/desenvolvedores conseguem seguir de forma consistente (alinhado ao objetivo de documentação/código consumível por agentes).
- Negativas/trade-offs: overhead de abstração (decorators, DI) maior que Express puro; performance bruta é levemente inferior a Fastify puro em benchmarks isolados — irrelevante frente ao gargalo real esperado (banco/rede), reavaliar apenas com evidência real (ver [../03-architecture/scalability.md](../03-architecture/scalability.md)).
- Decisões dependentes: estrutura de módulos em [../07-backend/backend-architecture.md](../07-backend/backend-architecture.md).
