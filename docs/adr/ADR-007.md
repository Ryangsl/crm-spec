# ADR-007: React + PWA para o frontend Mobile First

## Status
Aceito

## Contexto
O produto exige experiência primariamente mobile/tablet, com boa experiência em desktop, sem loja de aplicativos como requisito do MVP (ver [../01-product/vision.md](../01-product/vision.md) e [../06-frontend/responsive.md](../06-frontend/responsive.md)).

## Problema
Qual abordagem de frontend adotar para atender Mobile First com um único código-base, mantendo velocidade de desenvolvimento e sem depender de processo de publicação em loja de aplicativos para iterar rápido.

## Opções consideradas
1. **React + Vite + PWA** — SPA responsiva, instalável via navegador (manifest + service worker), um único código-base para mobile/tablet/desktop.
2. **React Native (app nativo)** — melhor integração com recursos nativos do dispositivo (notificação push nativa robusta, acesso a hardware), mas exige base de código adicional (ou compartilhamento parcial complexo) e processo de publicação em loja, incompatível com "sem overengineering no MVP".
3. **Framework mobile-first diferente de React (ex.: Vue/Svelte) + PWA** — viável tecnicamente, mas sem justificativa de trade-off superior a React para este time/ecossistema (React tem maior disponibilidade de componentes e integrações TanStack Query/RHF/Zod já adotadas, ver [../06-frontend/frontend-architecture.md](../06-frontend/frontend-architecture.md)).

## Decisão
Adotar **React + TypeScript + Vite + PWA**, com Tailwind CSS, TanStack Query, React Hook Form e Zod (ver [../06-frontend/frontend-architecture.md](../06-frontend/frontend-architecture.md)).

## Consequências
- Positivas: um único código-base cobre mobile, tablet e desktop; instalável (PWA) sem processo de loja, permitindo iteração rápida no MVP; ecossistema maduro alinhado ao restante da stack escolhida.
- Negativas/trade-offs: recursos nativos avançados (push notification totalmente nativa e confiável em segundo plano, acesso profundo a hardware) são mais limitados via PWA do que via app nativo — aceitável para o MVP e fases próximas; app nativo (React Native ou outro) fica como possibilidade futura (`[DECISÃO PENDENTE]`, ver [../01-product/vision.md](../01-product/vision.md) seção 7), a ser decidido com um novo ADR quando houver evidência de necessidade real (ex.: dependência forte de push notification em segundo plano para operadores de call center).
