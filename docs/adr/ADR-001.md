# ADR-001: PostgreSQL como banco de dados principal

## Status
Aceito

## Contexto
O sistema precisa de um banco relacional que suporte um modelo de dados com muitas relações (clientes, leads, oportunidades, atendimentos), multi-tenancy via coluna discriminadora, transações ACID para regras de negócio (ex.: mudança de etapa de oportunidade) e capacidade de evoluir para particionamento/read replicas conforme o volume cresce.

## Problema
Qual tecnologia de armazenamento de dados adotar como principal, considerando maturidade, custo operacional, compatibilidade com o ecossistema Node.js/TypeScript escolhido e capacidade de escalar no futuro sem reescrita.

## Opções consideradas
1. **PostgreSQL** — relacional, open-source, maduro, suporta JSONB (campos flexíveis), Row Level Security, particionamento nativo, extensões (`pg_trgm` para busca).
2. **MySQL/MariaDB** — relacional, também maduro, ecossistema um pouco mais limitado em recursos avançados (RLS nativo, JSONB tão rico) relevantes para multi-tenancy.
3. **MongoDB (NoSQL)** — flexível para esquema variável, mas o domínio do produto (CRM/pipeline/relacionamentos fortes) é fundamentalmente relacional; consistência transacional entre entidades relacionadas seria mais difícil de garantir.

## Decisão
Adotar **PostgreSQL** como banco de dados principal do sistema.

## Consequências
- Positivas: suporte nativo a Row Level Security (defesa adicional de multi-tenancy, ver [../03-architecture/security.md](../03-architecture/security.md)), JSONB para campos flexíveis (`custom_fields`, `settings`), particionamento nativo para escalabilidade futura, ecossistema maduro com Prisma.
- Negativas/trade-offs: nenhuma vantagem relevante de NoSQL (escrita massivamente não estruturada) é aproveitada — aceitável, pois não é o perfil de dado do produto.
- Decisões dependentes: [ADR-004](ADR-004.md) (multi-tenancy), modelo de dados em [../04-database/](../04-database/).
